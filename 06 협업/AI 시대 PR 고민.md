AI를 사용하기 이전에는 기능을 구현하는데 비용이 많이 들어 pr이 올라오는 횟수가 적었고 그래서 pr리뷰를 할 양이 적었다.

하지만 정글에서 나만무 프로젝트에서 AI를 풀로 사용하면서 하루에도 엄청난 양의 코드 변경이 생기고 많은 수의 pr이 올라왔다.

그렇게 되니 pr을 읽어보기는 힘들어 졌고, codex 한테 리뷰를 맡기는 정도로 체크를 하고 머지하는 식으로 작업을 진행하게 됐다.

프로젝트는 무사히 끝냈지만 AI에 리뷰를 맡기고 머지하는 방식에는 불안감이 있어 어떻게 pr을 진행하는지 찾아보고 싶어서 작성하게 됐다.

## [PR을 더 느리게 만들기 위한 고민 - 카카오페이 테크 블로그](https://tech.kakaopay.com/post/kakaopayins-slow-pr-fast-dev/)

코드 생산 속도가 빨라졌지만 머지에 병목이 생기는 문제가 발생

### 해결 방법

**task를 작개 쪼개는 일을 AI에게 맡긴다.**

**PR 템플릿을 재정의 했다.**
```
# 해결하려는 문제가 무엇인가요?
# 왜 해야 하나요?
# 어떻게 해결했나요?
# 이 PR의 한계 & 트레이드오프
# 기존 기능에 미치는 영향
# Edge Case & 실패 시나리오
# 검토한 대안과 선택 이유
# 리뷰 포인트 (파일/영역별 Risk 🔴🟡🟢)
```

**AI 리뷰어 조르깃을 만들었다.**
4단계로 리뷰를 자동 수행한다.
```
PR opened → Step 1: 언어 관점
          → Step 2: 프레임워크/인프라
          → Step 3: 도메인/보안
          → Step 4: 최종 검증 → 인라인 코멘트 + 요약
```
다음과 같은 태그도 붙여준다.
- `[r]` 꼭 반영해 주세요
- `[c]` 웬만하면 반영해 주세요
- `[a]` 사소한 의견입니다

**AI 리뷰 위에 사람의 리뷰를 얹었다.**
```
PR 생성
  ↓ (2분)
jorgit — 구조적 품질 스캔
  ↓
작성자 1차 피드백 반영
  ↓ (2h 50m)
사람 리뷰어 — 비즈니스 판단 + 최종 승인
  ↓ (2h 40m)
머지
```
AI 리뷰 덕분에 사람이 집중해야할 영역을 좁힐 수 있었다.

**모든 pr을 같은 무게로 다루지 않았다.**

| 변경 유형          | 사람이 판단할 것        | AI만으로 충분한가 |
| -------------- | ---------------- | ---------- |
| 리네임/포맷팅        | 빠뜨린 곳이 없는가?      | ✅          |
| 테스트 추가         | 기존 동작을 깨뜨리지 않는가? | ✅          |
| 메서드 추출 (동작 동일) | 구조가 나아졌는가?       | ✅          |
| 비즈니스 로직 변경     | 이 동작이 맞는가?       | ❌          |
| 새로운 패턴 도입      | 이 방향이 맞는가?       | ❌          |
| 트레이드오프가 있는 설계  | 이 비용을 수용할 것인가?   | ❌          |


나에게 필요하다 생각한점 
1. AI를 활용해 설계를 진행하고 task는 사람이 리뷰하게 쉽게 더 작게 쪼갠다.
2. 코드 리뷰와 같은 부분은 AI에게 맡기고 비지니스 판단과 같은 리뷰는 사람이 한다.
3. 작업을 분류해 AI 리뷰만으로 충분한 작업들은 AI 리뷰만 진행
