
넓은 의미에서 HTTP 요청을 받는 서버라면 둘 다 웹 서버 역할을 한다고 볼 수 있다.

보통 **HTML/CSS/JS와 같은 정적 파일을 제공하는 서버를 웹서버**라고 한다.

프로그램이 **요청을 받고 로직을 실행하는 서버를 백엔드 서버, API 서버, 애플리케이션 서버**라고 한다.

브라우저의 HTTP 요청 흐름은 항상 프론트 서버를 거치는 것은 아니다.

1. 프론트 서버가 백엔드 요청을 중계하는 구조도 있고,
```
브라우저 → 프론트 서버 → 백엔드
```
2. 브라우저가 백엔드를 직접 호출하는 구조도 있다.
```
브라우저 ─────→ 프론트 서버
     └──────→ 백엔드 서버
```

**그럼 두 가지 요청 방식이 SSR/CSR 인가?**

SSR = HTML을 서버에서 렌더링해서 보내는 방식
```
브라우저
  ↓ 페이지 요청
프론트 서버(예: Next.js)
  ↓ 필요하면 API/DB 조회
백엔드 서버
  ↓
DB

프론트 서버가 완성된 HTML 생성
  ↓
브라우저에 HTML 전달
```

CSR = 브라우저에서 화면을 렌더링하는 방식
```
브라우저
  ↓
프론트 서버/CDN
  ↓
HTML + JS 다운로드

브라우저에서 JS 실행
  ↓
백엔드 API 직접 호출
  ↓
DB

받은 데이터로 브라우저가 화면 생성
```

- SSR/CSR은 요청 경로가 아니라 **HTML을 어디서 만들어서 렌더링하냐**의 차이이다.
