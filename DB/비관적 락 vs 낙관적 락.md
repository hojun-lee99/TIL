## 락 이란?
공유자원의 동시성 문제를 제어하기 위한 방법

비관적 락과 낙관적 락은 주로 DB의 동시성 문제를 제어하기 위한 방법

## 비관적 락
데이터를 접근할 때 작업 끝날때까지 락을 걸고 다른 작업이 처리하지 못하게 막는 방식

```sql
SELECT * FROM account
WHERE id = 1
FOR UPDATE;
```
db의 기능을 이용`FOR UPDATE`를 사용해 트랜잭션이 끝날때까지 해당 데이터에 대한 물리적인 락이 걸리게 된다.

## 낙관적 락
락을 걸지 않고 읽은 뒤 저장할때 버전이 같은지 비교하는 방식

```sql
UPDATE account
SET balance = 150, ver = 2
WHERE id = 1 AND ver = 1;
```
어플리케이션 레벨에서 제어 버전이 달라 RowCount가 0이 반환이 되면 재시도와 같은 후속 작업을 진행하도록 작업한다.

| 구분    | 비관적 락      | 낙관적 락     |
| ----- | ---------- | --------- |
| 락 방식  | DB 락       | 어플리케이션 레벨 |
| 성능    | 느림 (대기 발생) | 빠름 (락 없음) |
| 충돌 시  | 대기 후 처리    | 실패 후 재시도  |
| 적합 상황 | 충돌이 잦을 때   | 충돌이 드물 때  |
## 언제 사용할까?
### 비관적 락
데이터 정합성이 매우 중요할 때 (계좌 이체, 재고 차감)
충돌이 빈번하게 일어날 때 (선착순 이벤트)

### 낙관적 락
성능이 중요하고 충돌이 적을 때 (게시글 수정, 수강신청)
조회와 수정 사이의 텀이 길 때 (위키 편집, 관리자 페이지)

---
Q1. 낙관적 락에서 실패하면 어떻게 처리하나요?
- 사용자에게 다시 시도해달라는 에러 메시지를 보여주거나, 자동 재시도 로직을 구현합니다.
Q2. 비관적 락 사용 시 주의할 점
- 서로 다른 자원을 쥐고 놓지 않는 데드락 발생 가능성이 있으므로 순서를 주의해야 합니다.
Q3. JPA에서는 어떻게 구현하나요?
- `@Version` 어노테이션으로 낙관적 락을, `LockModeType.PESSIMISTIC_WRITE`로 비관적 락을 쉽게 적용할 수 있습니다.
