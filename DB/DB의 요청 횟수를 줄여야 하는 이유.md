N+1 문제를 해소하면 성능이 확연히 개선되는 이유가 궁금해서 찾아보았다.

## DB 쿼리 1회 요청에 걸리는 비용

### 1. 네트워크 왕복(RTT) 비용
일반적으로 어플리케이션 서버와 DB 서버는 물리적으로 다른 머신에 분리되어 있기 때문에, 쿼리 1건마다 네트워크를 왕복하게 된다.

같은 클라우드 리전이여도 0.5~1ms 수준이라고 한다. 쿼리가 100번이면 쿼리 내용과 무관하게 왕복 비용만 100번 발생하게 된다.

### 2. DB 서버의 쿼리 처리 (CPU)
DB가 쿼리를 받으면 SQL 파싱 -> 옵티마이저 실행 계획 수립 -> 실행 -> 결과 직렬화 과정을 거친다.

이 과정이 전부 CPU 작업이라, 쿼리 횟수가 많아지면 디스크가 한가해도 DB 서버의 CPU가 먼저 포화되는 문제가 발생한다.

### 3. 커넥션 비용
PostgreSQL은 커넥션 하나가 OS 프로세스 하나여서, 커넥션 수를 무한정 늘릴 수 없고 커넥션 풀을 사용해 커넥션을 관리한다. 요청 수가 많다는건 커넥션을 오래 붙잡기 때문에 한정된 커넥션 풀에서 대기가 발생한다.

### 4. 잠금과 트랜잭션 경합
쿼리가 많아지만 table/row lock을 잡는 횟수도 늘고, 잠금 경합이 발생하면 처리량이 급격히 떨어지게 된다.

### 5. 디스크 I/O
풀 스캔, 인덱스 미스, 캐시 미스와 같은 경우 디스를 I/O 비용이 발생할 수 있다.
